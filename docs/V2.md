## Plan

### Decisions (do not reopen)

- **A lane runs the real CLI.** It is a git worktree plus a tmux session running `claude` or `codex` inside the existing lane sandbox (bubblewrap).
  - Lanes have a new `kind: "cli" | "acp"`, defaulting to `cli` for Claude Code and Codex.
  - ACP stays for agents without a good TUI.
- **ContextLanes observes and gates through the agents' own hooks; it never scrapes the screen.** Claude Code and Codex both support PreToolUse and PermissionRequest hooks:
  - a hook can return allow or deny;
  - with no decision, the agent shows its own prompt.
- **Nothing in the terminal gets worse.** The owner can always type in the lane's tmux pane exactly as in a plain session. Web, phone, Telegram, ntfy and the CLI are additional ways in.
- **One answer per question.** A permission resolves once, whichever surface answers first. The others close.
- **If the daemon is unreachable, the agent behaves as a plain CLI.** Every hook returns "no decision" within 2 seconds.
- **Keep:** worktrees, recipes, runtime, previews, checker, review, judge, collisions, briefs, `delegate`, insights, sandbox, notifications, event log.
- **Demote:** the ACP step trail as the main view for CLI lanes.
- **Not copying:**
  - skip-permission defaults (Vibe Kanban);
  - LLM permission gates (ccgate, Codex guardian reviewer);
  - accounts or hosted relays (Tailscale stays the network);
  - voice, plugins, and Slack/Linear intake.

### V1 Hook bridge
*Borrowed from Claude Code and Codex lifecycle hooks.*

**`contextlanes hook <event>`** is a tiny entry point that starts fast: no daemon client bundle, it should start in under 100 ms.
- It reads the hook JSON on stdin and posts it to the daemon with the lane token from the environment.
- It prints the agent's expected JSON response.
- It exits 0 with no decision when the daemon cannot be reached within 2 seconds, or when the event carries no decision.

**Per-lane wiring, without touching user or repo config:**
- **Claude Code:** a per-lane settings file in the lane's data folder, passed with `--settings` (verify the flag). Hooks are merged with the user's settings, not replacing them; verify and record.
- **Codex:** per-lane hooks through `-c` config overrides or an overlay `CODEX_HOME` that layers the user's real config and login. Verify which works on the installed version.
  - Codex may require trusting new hooks (`/hooks`). Find the least-privileged way a lane's hooks can be trusted without editing the user's global trust list.
  - If none exists, record exactly what Kyle must approve once, in Needs Kyle.

**Events** (map each to existing protocol events where one exists; add new ones in protocol otherwise):

| Hook | Recorded as | Response |
|---|---|---|
| SessionStart | `agent.session` (session id, transcript path) | adds project notes as context (moves the first-prompt prefix here for CLI lanes) |
| UserPromptSubmit | the owner's message | none; marks the lane busy |
| PreToolUse | `tool.call` with tool name and input | runs `guard.ts`: dire actions are denied with the guard's reason; otherwise no decision |
| PermissionRequest | `permission.requested` | waits for an answer (below) |
| PostToolUse | `tool.result` with exit code and output capped at 12,000 characters | none |
| Stop | turn ended | none; marks the lane idle |
| Notification | `agent.notice` | none |

**PermissionRequest.**
- The hook posts the request, then waits for `permission.answered` (long-poll or SSE) and returns allow or deny with the owner's message.
- Set the hook timeout in the per-lane config to 24 hours, so the agent waits for a phone answer.
- In Auto, the daemon answers through the same path, and guard holds what it holds today.
- If the owner answers in the terminal instead, the agent moves on and the next event for that tool call resolves the request as answered in the terminal, so the Inbox clears.

**Fixtures and steps.**
- Capture real payloads for every event from both agents (scrubbed) and make tests replay them through the bridge.
- Usage keeps coming from the session JSONL (3.0 code), located through the SessionStart payload.
- Progress, Steps, collisions, insights, the judge and the nudges must work from hook events for CLI lanes. Reuse the existing event types so these consumers need few or no changes.

- **Done when:**
  - real Claude and Codex lanes record every tool call;
  - a permission answered in the web Inbox continues the agent;
  - Auto holds a dire command;
  - with the daemon stopped, the CLI prompts normally and keeps working;
  - fixture tests cover both agents.
