## Plan

### Decisions (do not reopen)

- **A lane runs the real CLI.** It is a git worktree plus a tmux session running `claude` or `codex` inside the existing lane sandbox (bubblewrap).
  - Lanes have a new `kind: "cli" | "acp"`, defaulting to `cli` for Claude Code and Codex.
  - ACP stays for agents without a good TUI.
- **ContextLanes observes and gates through the agents' own hooks; it never scrapes the screen.** Claude Code and Codex both support PreToolUse and PermissionRequest hooks:
  - a hook can return allow or deny;
  - with no decision, the agent shows its own prompt.
- **Nothing in the terminal gets worse.** The owner can always type in the lane's tmux pane exactly as in a plain session. Web, phone, Telegram, ntfy and the CLI are additional ways in.
- **One answer per question.** A permission resolves once, whichever surface answers first. The others close.
- **If the daemon is unreachable, the agent behaves as a plain CLI.** Every hook returns "no decision" within 2 seconds.
- **Keep:** worktrees, recipes, runtime, previews, checker, review, judge, collisions, briefs, `delegate`, insights, sandbox, notifications, event log.
- **Demote:** the ACP step trail as the main view for CLI lanes.
- **Not copying:**
  - skip-permission defaults (Vibe Kanban);
  - LLM permission gates (ccgate, Codex guardian reviewer);
  - accounts or hosted relays (Tailscale stays the network);
  - voice, plugins, and Slack/Linear intake.

**Drop-in wrapper.**
- `contextlanes claude [args…]` and `contextlanes codex [args…]` work from inside a registered repository (register it if it isn't, as `contextlanes add` does).
- Default: create a lane (worktree, branch, tmux) and attach the current terminal to it. Pass extra args through to the agent unless they are on the forbidden list.
- `--here`: direct mode. The lane uses the current checkout with no worktree. It counts as a lane on the current branch for collisions, and Clean up never removes a direct-mode checkout.
- Detaching uses tmux's normal key and leaves the lane running. `contextlanes term <lane>` reattaches, as today.

**Web lane page.** For CLI lanes the Terminal view is the default and fills the main area. Progress and Steps stay as tabs, filled by V1.

**Restart the agent and Delete** work for CLI lanes: the agent is restarted in the same tmux session; resume is used if the CLI supports it (verify `claude --resume`/`--continue`, `codex resume`).

### V1 Hook bridge
*Borrowed from Claude Code and Codex lifecycle hooks.*

**`contextlanes hook <event>`** is a tiny entry point that starts fast: no daemon client bundle, it should start in under 100 ms.
- It reads the hook JSON on stdin and posts it to the daemon with the lane token from the environment.
- It prints the agent's expected JSON response.
- It exits 0 with no decision when the daemon cannot be reached within 2 seconds, or when the event carries no decision.

**Per-lane wiring, without touching user or repo config:**
- **Claude Code:** a per-lane settings file in the lane's data folder, passed with `--settings` (verify the flag). Hooks are merged with the user's settings, not replacing them; verify and record.
- **Codex:** per-lane hooks through `-c` config overrides or an overlay `CODEX_HOME` that layers the user's real config and login. Verify which works on the installed version.
  - Codex may require trusting new hooks (`/hooks`). Find the least-privileged way a lane's hooks can be trusted without editing the user's global trust list.
  - If none exists, record exactly what Kyle must approve once, in Needs Kyle.

**Events** (map each to existing protocol events where one exists; add new ones in protocol otherwise):

| Hook | Recorded as | Response |
|---|---|---|
| SessionStart | `agent.session` (session id, transcript path) | adds project notes as context (moves the first-prompt prefix here for CLI lanes) |
| UserPromptSubmit | the owner's message | none; marks the lane busy |
| PreToolUse | `tool.call` with tool name and input | runs `guard.ts`: dire actions are denied with the guard's reason; otherwise no decision |
| PermissionRequest | `permission.requested` | waits for an answer (below) |
| PostToolUse | `tool.result` with exit code and output capped at 12,000 characters | none |
| Stop | turn ended | none; marks the lane idle |
| Notification | `agent.notice` | none |

**PermissionRequest.**
- The hook posts the request, then waits for `permission.answered` (long-poll or SSE) and returns allow or deny with the owner's message.
- Set the hook timeout in the per-lane config to 24 hours, so the agent waits for a phone answer.
- In Auto, the daemon answers through the same path, and guard holds what it holds today.
- If the owner answers in the terminal instead, the agent moves on and the next event for that tool call resolves the request as answered in the terminal, so the Inbox clears.

**Fixtures and steps.**
- Capture real payloads for every event from both agents (scrubbed) and make tests replay them through the bridge.
- Usage keeps coming from the session JSONL (3.0 code), located through the SessionStart payload.
- Progress, Steps, collisions, insights, the judge and the nudges must work from hook events for CLI lanes. Reuse the existing event types so these consumers need few or no changes.

- **Done when:**
  - real Claude and Codex lanes record every tool call;
  - a permission answered in the web Inbox continues the agent;
  - Auto holds a dire command;
  - with the daemon stopped, the CLI prompts normally and keeps working;
  - fixture tests cover both agents.

#### V1 implementation evidence (2026-11-01)

- **Implemented:** a Node-only `contextlanes hook <event>` bootstrap; authenticated, lane-scoped hook routes; per-lane Claude `--settings` and Codex `CODEX_HOME/agent/hooks.json`; 24-hour permission hooks with 250ms answer polling. Initial connection or subsequent polling failure returns no decision within two seconds. No bypass flags, global settings edits or model-based approver were introduced.
- **Decided:** PostToolUse uses the existing `tool.update` event, preserving Progress, Steps, checks, judge, collision, helper and nudge consumers. SessionStart records the native session id and transcript path, adds project notes, and leaves baseline lanes without notes. The transcript path is an observation; usage reads only the lane-local log matched by both session id and checkout. Cumulative `usage.snapshot` events preserve usage deltas across daemon reconstruction.
- **Verified native shapes:** both agents supply `session_id`, `transcript_path`, `cwd`, `hook_event_name`; PreToolUse/PostToolUse add `tool_name`, `tool_input`, `tool_use_id`. PermissionRequest omits `tool_use_id`; Codex adds a description absent from its corresponding PreToolUse input, so correlation ignores that description. Stop includes `last_assistant_message`. Scrubbed real fixtures are in `apps/daemon/test/fixtures/hooks/{claude,codex}`. Codex 0.166 has no Notification hook; none was fabricated.
- **Verified responses:** PreToolUse denial is `{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"deny","permissionDecisionReason":"…"}}`. PermissionRequest returns `{"hookSpecificOutput":{"hookEventName":"PermissionRequest","decision":{"behavior":"allow"}}}` or `behavior: "deny", message: "…"`. Empty output means no decision. Only owner answers and the existing fixed guard can grant a permission; terminal completion merely clears the request and returns no decision. See the official [Claude hook reference](https://code.claude.com/docs/en/hooks) and [Codex hook reference](https://learn.chatgpt.com/docs/hooks).
- **Verified settings and trust:** a separate SessionStart marker from the lane's user settings ran alongside the generated Claude hook, proving `--settings` merges rather than replaces. Codex accepted the overlay's seven generated hooks through `/hooks`: select the event, inspect the User config entry ending in `agent/hooks.json`, press `t`. Unrelated plugin hooks were left untrusted. Codex saves its own `trusted_hash` under `[hooks.state."<source-path>:<event>:<group>:<handler>"]` in the overlay's config.toml. That trust survived resume. ContextLanes never manufactures it or changes the global trust list; each new overlay requires native review.
- **Verified real permissions:** Claude and Codex each continued a tiny `/tmp` task after Allow once in Chromium at 390px. Both recorded their tool calls, completion text and native JSONL token usage. Codex's Bash PostToolUse payload has an empty `tool_response` in this installed version: its JSONL `event_msg/item_completed` supplies the matching `CommandExecution.id`, `aggregated_output` and `exit_code`, restored to tool updates at Stop. The captured fixture covers this fallback. Claude's successful Bash hook omits an exit code, so it stays unknown.
- **Verified fallback and terminal answers:** stopped only the throwaway daemon while both agents waited. Both native permission dialogs were visible at 1,851ms or earlier. Restored the daemon, answered through each terminal, and both wrote `terminal.txt` containing `hi`; both requests cleared with `by: "terminal"`, without a second approval. A new native prompt also clears hook requests whose completion was missed while offline, preserving separate ask_owner questions.
- **Verified speed and safety:** seven cold `contextlanes hook SessionStart` runs took 27–30ms (median 28ms). Tests cover a hanging daemon's <2s fallback, native response polling, cross-lane/auth/body refusal, single-use owner answers, fixed-guard denial/replay, Auto allowing safe requests and holding dire ones, terminal reconciliation, real fixtures and usage. `pnpm check`: 365 passed, 9 opt-in tests skipped; typecheck and build passed. One older socket fixture now explicitly selects ACP; the helper redo test waits for its actual result instead of assuming 50ms.
- **Blocked — native Codex terminal approval:** on Codex 0.166, an outstanding synchronous PermissionRequest hook shows “Running hook”; the ordinary terminal Allow/Deny dialog appears only after the hook returns. Claude shows its native dialog concurrently. Codex's supported hook response has only allow/deny/no-decision; none both keeps a remote answer pending and exposes the native approval dialog. Disabling its hook would remove remote answers, and bypassing approvals violates the plan. The remote path, native interruption and daemon-loss fallback work; simultaneous native approval remains an upstream CLI gap. Codex CLI lanes remain available as required, and ACP remains selectable.

### V2 Answer and type from anywhere

**Composer input for CLI lanes** goes into the tmux pane:

### V5 Agents orchestrate lanes
*Borrowed from Superset (MCP), Paseo (agents launch agents), Kanban Code (`--json` for a master agent) and claude-team.*

**Toolbox tools** (lane token):
- `lanes_list`: this project's lanes with state, agent and last checkpoint.

- `contextlanes lanes --json`;

**Rules.** Sub-lanes still cannot spawn lanes. A bench baseline lane gets none of these tools.
